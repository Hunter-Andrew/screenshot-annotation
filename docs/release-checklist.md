# Release checklist

Before each release run the **Quick check** below by hand on the Windows test PC (about 10 minutes); the full list further down is reference for the parts you changed. Install the setup `.exe` from the candidate build (a CI artifact, or the draft Release), not a local build. Tag `vX.Y.Z` only once everything that applies passes. See [ADR 0006](adr/0006-manual-updates-unsigned-no-network.md).

Each item shows the milestone it applies from: **M0** (v0.1.0), **M1** (v0.2.0), **M2** (v0.3.0), **M3** (v0.4.0), **M4** (v0.5.0), **M5** (v0.6.0), **M6** (v1.0.0). In the full list, an item applies to every release at or after its milestone; the Quick check already picks the ones that matter most.

## Quick check (about 10 minutes): what goes unnoticed or does harm if broken

Run just these before tagging. They cover silent data loss and things that stop the app doing its job; the automated tests cannot see the real Windows behavior behind them. The long list below is reference: run the part that matches what you changed.

For v0.3.0 (M2):

- [ ] **Upgrade keeps your data.** Install the previous release, edit an image (draw, type text), change a setting (for example a tool color), then run the new setup over it. Afterwards the settings, `Pictures\Screenshot Annotation` images, tool styles and the image's undo history are all still there.
- [ ] **Edits survive a restart.** Draw something, wait for "All changes saved", quit from the tray, start the app and open the editor: the annotations are still editable and Ctrl+Z still undoes them.
- [ ] **What leaves the app is the finished picture.** With annotations on an image, Copy and paste into Teams or Outlook, and Save as PNG…: both show the annotations burned in, as a plain image.
- [ ] **Settings does not freeze the editor.** Open Settings from the editor gear and from the tray, close it and reopen it a few times; the editor stays responsive.
- [ ] **Typing never edits the picture.** In a Text box type a word, then use Backspace and Delete: only the words change, no annotation is deleted and no tool switches.
- [ ] **The app still comes back after sign-in.** Sign out and back in: the tray icon returns and the capture hotkey works.

For v0.4.0 (M3), on top of the v0.3.0 list above:

- [ ] **Delete is recoverable.** Hover a thumbnail in the Library Strip and click ✕: the image leaves the strip with no confirmation, an "Undo" notice appears, and the file is in the Recycle Bin (Explorer > Recycle Bin). Click Undo before the notice ends: the image is back in the strip and in `Pictures\Screenshot Annotation\<month>` under the same name, still editable. (The Recycle Bin keeps its own copy as well; see ADR 0008.) Then delete two thumbnails with Ctrl+click and the Delete key, and do the same from "All captures".
- [ ] **Reopening keeps annotations editable.** Draw an arrow and a text, open another thumbnail, then click the first one again: the arrow and text are there, selectable and movable, and Ctrl+Z still undoes them. Quit from the tray, start the app: the newest capture is on show.
- [ ] **The folder is the truth.** With the editor open, delete a PNG in Explorer: its thumbnail disappears within a few seconds (or at once when you click back into the app). Copy a screenshot PNG from elsewhere into a month folder: it appears in the strip and opens with no annotations, and the file is unchanged until you edit it.
- [ ] **Hover Copy pastes the finished picture.** Hover a thumbnail that has annotations, click Copy, and paste into Teams or Outlook: the annotations are burned in, as a plain image.

For v0.5.0 (M4), on top of the lists above (tickets 22, 23 and 24 are only proven by these steps; the Linux test suite cannot see the Windows behavior). The full steps are in "Tray, delay timer and Settings" and "Speed" below:

- [ ] **Closing the editor keeps the app alive.** Click the editor's X: the window hides, the tray icon stays, the first time only a notice says the app is still running in the tray. Press the capture hotkey: it works. Click the tray icon: the editor comes back with your last image.
- [ ] **The pre-warmed windows are fast and never show up in the picture.** Right after starting the app, press the hotkey and capture a region: the overlay appears at once and the editor opens at once on release. Task Manager shows the app idling at roughly 50 to 150 MB, not growing capture after capture.
- [ ] **The editor is out of the picture of a capture started from it (minimized, immediate).** With the editor open, click the editor's Capture button (and, separately, press the capture hotkey): the editor is MINIMIZED (it goes to the taskbar, it is not hidden) and the capture starts at once, with only the short 150 ms settle and no extra wait (`capture.log` shows `editor was open: minimized for the capture` and the overlay appears well under a second later). Capture a region over where the editor was: no trace of the editor, and no trace of the minimize animation or a ghost frame of the window (no shrinking thumbnail, no faded edge, no half-drawn frame) is in the picture. Check this with the editor maximized, with it not maximized, and with it on a second monitor (capture on both monitors), a few times each, because the animation may still be on screen when the frame is grabbed (the risk of dropping the old 500 ms wait). If any trace shows, raise `HIDE_SETTLE` and tell Andrew. After the capture is finished or cancelled (Esc), the editor comes back in the state it was in (maximized stays maximized). With the editor already minimized or closed to the tray, the capture just starts. A delayed capture from the editor's top bar ("Capture in 3s") minimizes the editor at the start of the countdown, which is far longer than the animation, and Esc during the countdown brings it back.
- [ ] **The delay timer works and its countdown is not in the capture.** Tray menu > "Capture in 5s", open a menu in another app during the wait: the number follows the pointer, then the overlay opens with the menu in the frozen picture and no countdown number in it.
- [ ] **Launch at sign-in survives sign-out/in, and the checkbox is honest.** Fresh install: Settings shows "Launch at sign-in" ticked; sign out and in again: the tray icon returns. Untick it, sign out and in: no tray icon until you start the app yourself.

For v1.0.0 (M6), on top of the lists above (tickets 49 to 54; the Linux test suite cannot see any of this, and it needs two monitors of different scaling, for example a 24-inch monitor and a laptop screen). The full steps are in "Demo tools hotkeys", "Pointer highlight" and "Drawing mode" below:

- [ ] **The two demo hotkeys work, rebind, refuse clashes and survive a restart.** Ctrl+Shift+L toggles the pointer highlight and Ctrl+Shift+D toggles drawing mode, from any app. In Settings > Demo tools rebind each: the new key works at once and the old one does nothing. Print Screen, the capture hotkey, the other demo hotkey and a key another app already holds are refused with a message, and the old key keeps working. Quit from the tray and start the app: the rebound keys still work, and both tools start off.
- [ ] **The pointer dot looks the same on both screens and never gets in the way.** Dot on, on a 24-inch monitor and a laptop screen of a different scale: same apparent size on both, and it follows the pointer across the border. Click and drag through it onto buttons, links and title bars of other apps: everything works as without it. Only a left click shows the ripple (right, middle and wheel do not). Quit and start the app: the dot is off.
- [ ] **The dot, the toolbar and the ripple are not in a capture, but the drawings are.** With the dot on, or with drawings and the toolbar up, take a capture with the app's hotkey (and with Win+Shift+S): no dot, no ripple and no toolbar in the picture; the drawings are in it.
- [ ] **Drawing mode covers both monitors and gives way to apps.** Draw on both monitors; each drawing stops at its own monitor's edge. Click Use apps and work in a real app (click a link, type into Notepad): the drawings stay and the app below responds. Esc, and separately the hotkey, clear every drawing and remove the toolbar.
- [ ] **Both tools work over a PowerPoint slideshow and a screen-share window.** Start a slideshow (F5) and a screen share (Teams or Zoom): the dot and the drawings show over them and the pointer still clicks through the dot. Exclusive full-screen games are unsupported in v1.0 (ADR 0009); do not test them.
- [ ] **The drawing keys never type into another app.** With drawing mode on, Alt+Tab to another app and type A, R, P, H, Ctrl+Z, Ctrl+Y and Esc: they only act in that app; nothing is drawn or ended.
- [ ] **The editor's Pointer button works and excludes the tools.** The button at the bottom of the tool column turns the dot on and off, shows pressed while it is on, and no editor tool is usable while it is on. Choosing a tool turns the dot off; turning it off selects Select.
- [ ] **The instant capture with the editor minimized shows no ghost frame (carried over from v0.6.0).** Repeat the minimized, immediate capture check from v0.5.0 above once more, with the dot on: no trace of the editor, its minimize animation or the dot in the picture.

Already checked on earlier releases and only worth repeating if the installer or capture code changed: no-admin install, uninstall leaves `Pictures\Screenshot Annotation` alone, capture on all monitors, Teams and Outlook paste, Discard to the Recycle Bin.

## Full checklist (reference)

## Install and upgrade

- [x] **M0** Setup runs with no admin prompt. SmartScreen shows "More info → Run anyway" and the app installs per-user.
- [x] **M0** The tray icon appears and its menu works; Settings opens and About shows the right version.
- [x] **M0** "Check for updates" opens the Releases page in the browser. The app makes no other network calls.
- [x] **M0** Upgrade closes and relaunches the app. Install the previous release, start it (tray icon showing), then run the new setup over it. The setup must not ask you to close the app. When it finishes, the tray icon is back (leave "Run Screenshot Annotation" ticked on the last page), and About shows the new version. Repeat once from a command prompt with `Setup.exe /P` (passive): the app must come back on its own.
- [x] **M0** If the upgrade shows a reinstall page, leave the default ("Uninstall before installing"). If an uninstall wizard then appears, leave the delete-app-data box ("Delete the application data", our "Also delete app data" option) unticked and carry on. Tell Claude if the wizard appears: it should not need any input.
- [x] **M1** Upgrade keeps your data. Before upgrading, change a setting, take a capture so `Pictures\Screenshot Annotation` has a file, and note the folders `%APPDATA%\io.github.hunter-andrew.screenshot-annotation` and `%LOCALAPPDATA%\io.github.hunter-andrew.screenshot-annotation`. After upgrading, the setting, the file and both folders are all still there, with unchanged contents.
- [ ] **M2** Upgrade keeps tool styles and undo history: after upgrading, reopen the image you edited and the tool styles and the per-tool "Return to Select after drawing" choices are as you left them and Undo still steps back.
- [ ] **M3** Upgrade keeps the thumbnail cache: the Library Strip fills without a visible rebuild, and the cache folder under `%LOCALAPPDATA%\io.github.hunter-andrew.screenshot-annotation` still has its files.
- [x] **M0** Uninstall without the option: Settings > Apps > Uninstall, leave "Delete the application data" unticked. `Pictures\Screenshot Annotation` is untouched and both app data folders above remain.
- [x] **M0** Uninstall with the option: reinstall, then uninstall with "Delete the application data" ticked. Both app data folders are gone; `Pictures\Screenshot Annotation` is still untouched.

## Capture

- [x] **M1** The hotkey opens the overlay on each of the 3 monitors, including monitors left of or above the primary (negative virtual-screen coordinates) and monitors with different scaling. Each overlay covers exactly its monitor and shows that monitor's frozen picture, aligned with the real screen (no shift or stretch).
- [x] **M1** Region, window and monitor capture each produce the right image (one monitor per capture).
- [x] **M1** Region mode: dragging draws crosshair guides, dims outside the selection and shows the pixel size; dragging past the edge of the monitor you started on stops the region at that edge (try each edge, towards a neighbouring monitor); releasing captures at once with no adjust step; a click without a drag over the bare desktop captures nothing (over a window it captures that window, see the next item). M toggles a magnifier near the pointer (also when the pressed overlay is on another monitor than the pointer). Esc cancels with nothing saved and the editor comes back if it was open.
- [x] **M1** Window mode: hovering highlights the window under the pointer (the topmost one where windows overlap: a dialog wins over the window behind it) and shows its pixel size; the bare desktop, a minimised window and a window on another virtual desktop are not highlighted. Clicking captures only that window's visible rectangle: no drop shadow and no invisible resize border (compare the file with the highlight and with the window in Explorer's snap layout; a maximised window must not include the 8 px that hang over the monitor edge), and a part covered by another window shows that window, not the hidden content. Put a window half across the border of two monitors (also across a monitor with different scaling) and click it on each side: each capture holds only the part on the clicked monitor. The overlay windows themselves are never highlighted, and the editor (if it was open) is not offered or in the picture. The file is at native resolution with no mouse pointer.
- [x] **M1** Region and Space captures are at native resolution (on a scaled monitor the image has the full physical pixel size, not the scaled size: a 300 x 200 pixel size label gives a 300 x 200 file), with no mouse pointer in it, and with the editor itself not in the picture even when it was open on that monitor. The result opens in the editor and is saved to the Library.
- [x] **M1** Ctrl+Shift+S opens the overlay; Space captures the whole monitor under the mouse pointer (check it on each monitor, and with the pointer on a different monitor than the one the key press reached). Tray menu "Capture" does the same as the hotkey. If Ctrl+Shift+S is taken by another app, the app still starts (the hotkey just does nothing).
- [x] **M1** Every capture appears in `Pictures\Screenshot Annotation\YYYY-MM\YYYY-MM-DD HHmmss.png` straight away. The file opens in Explorer and Photos showing the capture. Two captures in the same second get `-2` on the second. No `.tmp` files are left behind.
- [x] **M1** Close the editor, then confirm the hotkey still works from the tray.
- [ ] **M4** Capture from the editor's button minimizes the editor and captures at once: click Capture in the editor and capture the region it covered: no part of the editor and no trace of the minimize animation is in the picture. The screen is read 150 ms after the editor is minimized (`delay::wait_after_minimizing_editor`, the `HIDE_SETTLE` only, no extra wait); the hotkey with the editor closed has no wait at all. See the Windows check on the editor maximized and on a second monitor above.
- [ ] **M1** Sign out and back in; confirm the tray icon returns.
- [ ] **M1** If capture does nothing: the app now shows an error box naming the problem and the log path, and clears itself after 5 seconds if no overlay appears. Whatever happens, send Claude the log, `%APPDATA%\io.github.hunter-andrew.screenshot-annotation\capture.log` (the tray menu's "Open log folder" opens that folder; an older half is in `capture.log.1`). Press the hotkey once first so the log shows that attempt, then send the whole file.
- [x] **M1** Hotkey setting: in Settings click the hotkey field, press a new combination (for example Ctrl+Alt+K), and it shows at once and works without a restart (the old combination no longer does). Restart the app: the new hotkey is still in force. Pressing a combination another app owns (try Win+E or a hotkey from another running tool) shows a warning and leaves the old hotkey working.
- [ ] **M1** Print Screen notice: with Windows' "Use the Print screen button to open screen capturing" on, a fresh install opens Settings with the notice. "Open Windows setting" opens Settings at Bluetooth & devices (`ms-settings:bluetooth`; Microsoft documents no link straight to the Keyboard page); click Keyboard, and "Use the Print screen button to open screen capturing" is on that page (on some Windows builds it is under Accessibility > Keyboard instead). The app writes nothing there; flip the toggle yourself, then record Print Screen as the hotkey and check it opens the overlay and not Snipping Tool). The notice does not come back after either button, and not at all when the toggle was already off.

## Troubleshooting: Print Screen and `settings.json`

The app's data folder is `%APPDATA%\io.github.hunter-andrew.screenshot-annotation` (the `identifier` in `src-tauri/tauri.conf.json`). It holds `settings.json` and the diagnostics log `capture.log` (tray menu "Open log folder").

`settings.json` has more fields than the two below (`magnifier`, `toolStyles`, `launchAtSignIn`, `imageBackground` and `transparencyCheckerboard` (ticket 37; a value that is not one of the offered choices is read as the default), `canvasMargin` (0 to 200, default 16), `cropMargin` (0 to 400, default 150), `darkBackground` (`#RRGGBB`, default `#191919`; anything else is read as the default), `libraryStripCollapsed` (`true` when the Library Strip is collapsed), `outsideDarkness` (0 to 99.9, to a tenth) and `showOutsideDefault` (a number outside its range is brought into it), `pointerColor` (`#RRGGBB`, default `#e02424`), `pointerSize` (`small`, `medium` or `large`; default `medium`) and `pointerRipple` (default `true`) for the pointer highlight (anything else is read as the default; whether it is on is never stored), `trayNoticeShown`: the last is `true` once the one-time "still running in the tray" notice was shown; set it to `false` with the app closed to see it again). The two that matter for Print Screen:

- `hotkey`: the capture hotkey, e.g. `"ctrl+shift+s"` or `"PrintScreen"`. Change it in Settings, not by hand.
- `printScreenNoticeDismissed`: `true` means "you answered the one-time Print Screen notice" (you clicked either of its two buttons). It only stops that notice from showing again. It does not mean Print Screen works or that the Windows setting is off. To see the notice once more, quit the app, set it to `false`, and start the app.

If Print Screen is the hotkey and does nothing: Windows may still be giving the key to Snipping Tool. Settings shows a warning under the hotkey field while that is the case (it reads Windows live and clears itself when you return to the window after turning the setting off). Turn off "Use the Print screen button to open screen capturing" in Windows Settings > Bluetooth & devices > Keyboard (on some Windows builds, Accessibility > Keyboard); the app never changes that setting. If there is no warning and it still does nothing, send Claude `capture.log`: it records every hotkey registration and its result, every `set_hotkey` outcome, every hotkey press the app receives (`hotkey event: ...`), what the hotkey recorder received (`settings page: hotkey recorder: ...`), and the Windows setting reading (`PrintScreenKeyForSnippingEnabled=...`). No `hotkey event` line after pressing the key means Windows did not deliver it to the app. Bare Print Screen is not registered with `RegisterHotKey` at all: it is watched through Raw Input (ADR 0007), so look for `raw input: PrintScreen ...` lines instead; Windows still copies the whole screen to the clipboard when it is pressed, and the capture replaces that copy.
